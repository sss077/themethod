# Как запустить сайт — пошагово, без программирования

Займёт примерно 20–30 минут. Понадобятся: почта, браузер и папка с сайтом (та, где лежат `index.html`, `admin.html`, `config.js`, `schema.sql`).

---

## Шаг 1. Создайте проект в Supabase (база данных, бесплатно)

1. Откройте **https://supabase.com** → **Start your project** → войдите через GitHub или почту.
2. Нажмите **New project**.
3. Заполните:
   - **Name** — любое, например `autoschool-site`;
   - **Database Password** — нажмите **Generate a password** и сохраните пароль куда-нибудь (сайту он не нужен, но пригодится в будущем);
   - **Region** — выберите ближайший, например **Central EU (Frankfurt)**.
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся.

## Шаг 2. Создайте таблицы (выполните schema.sql)

1. В левом меню Supabase откройте **SQL Editor** (иконка `>_`).
2. Нажмите **New query** (или «+»).
3. Откройте файл `schema.sql` из папки сайта в любом текстовом редакторе (Блокнот, TextEdit), выделите **всё** (Ctrl+A / Cmd+A), скопируйте и вставьте в окно SQL Editor.
4. Нажмите **Run** (или Ctrl+Enter).
5. Внизу должно появиться **Success. No rows returned** — это нормально.

Что сделал этот файл: создал таблицы для кейсов, настроек, FAQ, команды, заявок; включил защиту (посетители могут только смотреть сайт и отправлять заявки); создал хранилище картинок `media`; заполнил сайт стартовыми текстами и тремя кейсами-заглушками с пометкой **[ЗАПОЛНИТЬ]**.

> Если запустить файл ещё раз — ничего не сломается и не задвоится.

## Шаг 3. Вставьте ключи в config.js

1. В Supabase откройте **Project Settings** (шестерёнка внизу слева) → **API** (в новых версиях: **Data API** и **API Keys**).
2. Скопируйте два значения:
   - **Project URL** — выглядит как `https://abcdefgh.supabase.co`;
   - ключ **anon public** (он же **publishable**) — длинная строка.
   > ⚠️ Ключ **service_role** / **secret** НЕ копируйте и никуда не вставляйте — он даёт полный доступ к базе.
3. Откройте файл `config.js` в текстовом редакторе и замените:
   ```js
   SUPABASE_URL: 'https://YOUR-PROJECT-ID.supabase.co',
   SUPABASE_ANON_KEY: 'YOUR-ANON-PUBLIC-KEY',
   ```
   на свои значения (кавычки оставьте). Сохраните файл.

> Публичный ключ `anon` можно не прятать: он виден любому посетителю сайта — так задумано. Защищают данные правила в базе (RLS), которые создал `schema.sql`.

## Шаг 4. Создайте свой аккаунт для входа в админку

1. В Supabase откройте **Authentication** → **Users**.
2. Нажмите **Add user** → **Create new user**.
3. Введите свой email и пароль, **поставьте галочку «Auto Confirm User»** → **Create user**.

## Шаг 5. Сделайте этот аккаунт администратором

Без этого шага войти получится, но редактировать сайт будет нельзя.

1. Снова откройте **SQL Editor** → **New query**.
2. Вставьте команду, **заменив email на свой** (тот, что указали в шаге 4):
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'ваш@email.com'
   on conflict (user_id) do nothing;
   ```
3. Нажмите **Run** (один раз). Должно появиться сообщение об успехе.
4. Проверьте, что вы в списке админов:
   ```sql
   select u.email from public.admins a join auth.users u on u.id = a.user_id;
   ```
   Если в ответе ваш email — готово. Если пусто — email введён не так, как в шаге 4.

> Ошибка `duplicate key value violates unique constraint "admins_pkey"` (если вы запускали старый вариант команды дважды) означает, что аккаунт **уже** админ — всё в порядке.

## Шаг 6. Закройте регистрацию посторонним

1. **Authentication** → **Sign In / Providers** (в старых версиях: **Providers** или **Settings**).
2. Выключите **Allow new users to sign up** → **Save**.

Теперь новых пользователей можно добавлять только вручную (шаги 4–5).

## Шаг 7. Выложите сайт в интернет

### Вариант А — Netlify (проще всего, перетаскиванием)

1. Откройте **https://app.netlify.com/drop** и зарегистрируйтесь (можно через почту).
2. Перетащите **всю папку сайта** в окно браузера.
3. Через несколько секунд появится ссылка вида `https://random-name-123.netlify.app` — это ваш сайт.
4. Поменять имя: **Site configuration** → **Change site name**. Подключить свой домен: **Domain management** → **Add a domain**.

**Обновить сайт** после изменения файлов (например, `config.js`): в Netlify откройте свой сайт → вкладка **Deploys** → перетащите папку ещё раз в область «Drag and drop your project folder here».

> Кейсы, цены, тексты, FAQ и команду менять через Netlify **не нужно** — это делается в админке, изменения появляются на сайте сразу.

### Вариант Б — Vercel

1. Зайдите на **https://vercel.com** → **Add New…** → **Project**.
2. Проще всего — загрузить папку в репозиторий GitHub и выбрать его в Vercel (**Import**). Framework Preset — **Other**, сборка не нужна → **Deploy**.

## Шаг 8. Проверьте, что всё работает

1. Откройте ваш сайт — должны появиться все блоки.
   Если видите надпись «Сайт ещё не подключён к базе» — проверьте `config.js` (шаг 3) и загрузите папку заново.
2. Откройте **ваш-сайт/admin.html**, войдите email/паролем из шага 4.
3. Зайдите в **Настройки** → блок **Контакты** → впишите свой **Telegram** (username без @) и/или **WhatsApp** (номер вида `998901234567`) → **Сохранить**. Без этого кнопки отправки заявки будут просто сохранять её в базу, не открывая мессенджер.
4. Отправьте тестовую заявку с сайта — она появится в админке в разделе **Заявки**.
5. Замените всё с пометкой **[ЗАПОЛНИТЬ]**: кейсы (раздел **Кейсы**) и команду (раздел **Команда**).

## Как пользоваться админкой

| Раздел | Что там |
|---|---|
| **Заявки** | Все заявки с сайта. Фильтр по городу, бюджету, статусу; статусы «Новая / В работе / Клиент / Отказ»; заметки; кнопка **Экспорт в CSV** (открывается в Excel/Google Таблицах). |
| **Кейсы** | Добавить, изменить, дублировать, удалить, порядок — перетаскиванием ⠿ или стрелками ↑↓. Черновики на сайте не видны. |
| **Настройки** | Цены оффера, текст гарантии, цифры-счётчики, Telegram, WhatsApp, телефон, Instagram, тексты кнопок. |
| **Секции** | Включить/выключить любой блок сайта, поменять порядок, заголовки и пункты меню. |
| **Боли / Что входит / Как работаем / FAQ / Команда** | Карточки блоков: добавить, изменить, скрыть, удалить, порядок. |

**Правила оформления текстов** (работают везде):
- `*слово*` в звёздочках — станет **красным** (например `МАРКЕТИНГ ДЛЯ *АВТОШКОЛ*`);
- строка, которая начинается с `- ` (минус и пробел) — станет пунктом списка с красным ▲;
- у каждого текста два поля: **RU** и **UZ**. Если узбекское поле пустое, на узбекской версии покажется русский текст.

**Картинки** сжимаются автоматически прямо в браузере (до 1600 px, формат WebP), поэтому можно загружать фото прямо с телефона.

**Посмотреть черновик кейса до публикации:** войдите в админку, затем в списке кейсов нажмите ↗ — пока вы вошли, черновик откроется в этом же браузере.

## Частые проблемы

- **«Нет прав…» при сохранении** — не выполнен шаг 5 или в нём другой email.
- **«Неверный email или пароль»** — проверьте шаг 4; пароль можно сменить в Supabase: **Authentication → Users → … → Reset password** / **Update user**.
- **Сайт пустой / «Не удалось загрузить данные»** — проверьте ключи в `config.js`. Также бесплатный проект Supabase **засыпает после 7 дней без посещений**: зайдите в панель Supabase и нажмите **Restore project**. Пока на сайт регулярно заходят люди, проект не засыпает.
- **Не открывается Telegram после заявки** — проверьте username в **Настройках** (без @ и пробелов). Заявка при этом всё равно сохраняется в разделе **Заявки**.
- **Мелкие надписи формы** (подписи полей, тексты кнопок «Отправить в Telegram» и т. п.) хранятся в файле `assets/js/core.js`, в блоке `UI` — их меняют редко; все остальные тексты меняются в админке.

## Что где лежит

```
index.html        — главная страница
case.html         — страница кейса (case.html?slug=...)
admin.html        — админка
config.js         — ключи Supabase (единственный файл, который нужно отредактировать)
schema.sql        — таблицы, права доступа, хранилище, стартовые тексты
assets/css/       — стили сайта и админки
assets/js/        — логика сайта и админки
assets/img/       — иконка сайта
```
